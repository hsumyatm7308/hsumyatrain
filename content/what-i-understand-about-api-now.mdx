API ဆိုတာ URL လေးကို frontend မှာခေါ်သုံးတာပဲ မဟုတ်ဘူးလား?
တကယ်တော့ အဲ့ဒါက API မဟုတ်ဘူး။ API ရဲ့ အသုံးပြုပုံတစ်မျိုးကိုပဲ သိထားခဲ့တာ။

လွန်ခဲ့တဲ့ လတွေကအထိ API ဆိုတာ backend က ရေးထားတဲ့ function ရဲ့ URL လေးကို frontend မှာ လာထည့်ရုံပဲလို့ ထင်ခဲ့တဲ့သူပါဗျာ။ system နှစ်ခုကို ချိတ်ဆက်ပေးတာတို့၊ စာပွဲထိုးအနေနဲ့ လုပ်ဆောင်ပေးတာတို့ စသည်ဖြင့် စာတွေလည်းဖတ်တာ စုံလို့ပေါ့။ နောက်တော့မှ  ကိုယ်တိုင်က သုံးနေပေမယ့် ဘာကြီးမှန်း သေချာမသိတာမျိုးဖြစ်နေတာပဲ။

ခု နားလည်ပုံကတော့
“မင်း ငါ့နာမည်လေး ခေါ်ပြီး လိုအပ်တဲ့ အချက်အလက်‌ ပေးရုံနဲ့ ငါ ဒီအလုပ်ကို လုပ်ပေးမယ်”
ဆိုတာမျိုးပေါ့။

ရှာဖတ်ရင်းနဲ့မှ Math.random() တို့၊ localStorage.setItem() တို့လို ကိုယ်နေ့တိုင်းသုံးနေတဲ့ JavaScript ရဲ့ built-in API / Web API တွေထဲမှာလည်း URL မလိုတဲ့ API တွေ ရှိတယ်ဆိုတာ အဲ့တော့မှ သိလိုက်ရတယ်။

ကိုယ်က web ပိုင်းကဆိုတော့ RESTful API ဆိုတာကတော့ ကြားဖူးတာပေါ့။ အဲ့တာကြောင့် API ဆိုတာ URL ခေါ်သုံးရုံလို့ ထင်တာလည်း ပါတယ်။

Data ပို့တာ၊ ပြန်ယူတာတွေမှာ HTTP protocol သုံးတာတွေ ဘာညာတော့ သိတယ်ဆိုပါတော့။

နောက်တော့ client ဘက်က လိုချင်တဲ့ data ကိုပဲ သီးသန့် တောင်းလို့ရတဲ့ GraphQL တို့၊ SOAP တို့၊ RPC တို့လို ပုံစံတွေလည်း ရှိသေးတာ သိလာတယ်။

တစ်ခုနဲ့တစ်ခု ရေးပုံ၊ သုံးပုံ မတူကြဘူး။ဒါပေမယ့် အခြေခံအားဖြင့်တော့ API ဆိုတာ “ဘယ်လိုခေါ်ရမယ်၊ ဘာပေးရမယ်၊ ဘာပြန်ရမယ်” ဆိုတာကို ကြိုသတ်မှတ်ထားတဲ့ နည်းလမ်းတစ်ခုလို နားလည်လာတယ်။

အခုတော့ API ဆိုတာ URL လေးကောက်ထည့်ရုံပဲ သိတဲ့သူ မဟုတ်တော့ဘူးပေါ့နော်။

URL က API မဟုတ်ပါဘူး။
Web API တွေမှာ URL က API ကို အသုံးပြုဖို့အတွက် endpoint ရဲ့ address တစ်ခုအနေနဲ့ ပါလာတာမျိုးပါ။
အရင်က ကိုယ်သိခဲ့တာ မမှား‌‌ပေမယ့် မပြည့်စုံသေးတာပဲ။
